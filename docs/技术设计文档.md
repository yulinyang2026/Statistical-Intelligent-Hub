## 1. 文档说明

本系统为 PC 端 Web 管理系统，前后端分离架构。业务需求另行提供，本文档只约定**技术体系、工程结构、接口契约、存储方案与演进路径**，作为前后端并行开发的共同基线。

前端复用当前工程 `Statistical-Intelligent-Hub` 的全部技术体系与开发规范；后端新建 Java 17 + Spring Boot 3.x 工程。**一期不对接数据库与缓存**：数据落地为 JSON 文件存储，Redis 留到二期，以支撑前期高频的功能与数据结构调整。

### 4.2 工程结构（单模块 Maven，包分层）

```
backend/
├─ pom.xml
├─ src/main/java/com/<org>/admin/
│  ├─ AdminApplication.java
│  ├─ common/                        # 通用层
│  │  ├─ config/                     # Web、Jackson、CORS、OpenAPI 配置
│  │  ├─ controller/                 # 全局异常处理器、健康检查
│  │  ├─ response/                   # BaseResponse 统一响应体
│  │  └─ exception/                  # 业务异常体系（BizException + ErrorCode）
│  ├─ module/
│  │  ├─ auth/                       # 登录、登出、用户信息
│  │  │  ├─ controller/AuthController.java
│  │  │  ├─ service/AuthService.java
│  │  │  └─ dto/ (LoginRequest, LoginResponse, UserInfoResponse)
│  │  ├─ <bizmodule>/                # 业务模块（需求确定后按此模板复制）
│  │  │  ├─ controller/XxxController.java
│  │  │  ├─ service/XxxService.java（含 Impl）
│  │  │  ├─ dto/                     # 入参/出参 DTO（对外契约，禁止 Entity 直接出 Controller）
│  │  │  ├─ domain/                  # 领域对象（PO，字段即 JSON 文件字段=未来表字段）
│  │  │  └─ repository/              # 仅持有 Repository 接口引用
│  │  └─ ...
│  └─ storage/                       # 存储层（对业务透明）
│     ├─ EntityRepository.java       # 抽象接口（核心，见第 5 章）
│     ├─ json/                       # 一期实现
│     │  ├─ JsonFileRepository.java
│     │  └─ JsonFileStorageConfig.java
│     └─ dm/                         # 二期实现（达梦）
└─ src/main/resources/
   ├─ application.yml
   ├─ application-dev.yml / application-prod.yml
   └─ data/                          # JSON 数据文件 + seed 初始数据
      ├─ user.json
      └─ <module>/<entity>.json
```

分层约定：

- **Controller**：只做协议转换（DTO ↔ Service 调用），不写业务；返回统一 `BaseResponse`。
- **Service**：业务逻辑、事务边界（一期无真事务，见 5.3 限制说明）。
- **Repository**：数据访问，业务层只依赖 `EntityRepository<T>` 接口，**不知道**底层是 JSON 还是达梦。
- **DTO 与 Domain 分离**：接口字段调整只动 DTO；Domain 字段设计成与未来数据库表结构一致，二期建表即翻译 Domain。

### 4.3 管理小帮手（AI 对话，2026-09-10 新增）

> 系统首个**出网 HTTP 调用**与**流式响应**能力，技术选型如下；需求口径见 `docs/需求规格/17-AI智能助手.md`。

| 项 | 选型 | 说明 |
|---|---|---|
| 上游协议 | OpenAI 兼容 `chat/completions`（`stream=true`） | 兼容 DeepSeek / 通义 / Kimi / 智谱等，换供应商只改配置 |
| HTTP 客户端 | **JDK 17 自带 `java.net.http.HttpClient`** | 零新增依赖（工程无 WebFlux，故不用 WebClient）；连接复用 + 流式读 body |
| 流式转发 | `StreamingResponseBody` + `text/event-stream` | Servlet MVC 原生支持；上游 token 以 `data:{"content":"..."}` 转发，结束标志 `data:[DONE]`，错误以 `data:{"error":"..."}` 事件输出 |
| 配置 | `app.ai.*`（`AI_BASE_URL` / `AI_API_KEY` / `AI_MODEL` 环境变量占位） | 密钥不进代码库；`spring.mvc.async.request-timeout` 放宽至 5 分钟 |
| 存储 | 会话 / 消息两实体走既有 `JsonEntityRepository` | 二期达梦切换零 Service 改动 |
| 上下文 | 系统提示词 + 最近 `context-messages`（默认 10）轮历史 | 多轮对话记忆由后端拼装 |

**SSE 流式契约**（`POST /api/chat/sessions/{id}/stream`）：

- 请求体 `{ "content": "..." }`（`@Valid` 非空）；用户提问在流开始前落库，此时参数/鉴权/会话归属错误仍走统一 JSON 错误体（HTTP 200 + code 400）。
- 响应 `Content-Type: text/event-stream`，`Cache-Control: no-cache`、`X-Accel-Buffering: no`；前端用原生 `fetch` + `ReadableStream` 读取（axios 拦截器契约不适配流式）。
- 流结束后 AI 回答整体落库；客户端中途断开时已累积内容仍落库。

## 5. 数据存储设计（一期 JSON → 二期达梦）

### 5.1 核心抽象：EntityRepository

一切为了"换库不改 Service"。接口按集合语义设计，与 MyBatis-Plus 的 IService/BaseMapper 心智对齐，二期实现时映射成本低：

```java
public interface EntityRepository<T, ID> {

    T findById(ID id);

    List<T> findAll();

    /** 条件查询 + 分页，sort 字段白名单由各模块实现校验 */
    PageResult<T> findByCondition(Map<String, Object> condition, int current, int size);

    T insert(T entity);            // 分配 ID 并落盘

    T updateById(T entity);        // 全量更新

    void deleteById(ID id);
}
```

```java
public record PageResult<T>(List<T> records, long current, long size, long total) {}
```

> `PageResult` 字段名 **records / current / size / total** 与前端 `Api.Common.PaginatedResponse` 逐字对齐，Controller 直接透传，不做二次组装。

### 5.2 一期：JsonFileRepository 实现要点

- **文件组织**：每类实体一个文件，`resources` 之外的外部目录（如 `${app.data-dir:./data}`），`<module>/<entity>.json`。**不打进 jar**，便于人工调整数据。
- **内存镜像 + 写穿**：启动时整体加载进内存（`ConcurrentHashMap`），增删改更新内存后整体序列化落盘。一期数据量约定 < 5 万条/实体，整体读写性能与一致性可接受。
- **原子写**：先写 `<file>.tmp` 再 `Files.move(..., ATOMIC_MOVE)`，避免半截文件；进程崩溃最多丢最后一次写。
- **并发控制**：每实体一把 `ReentrantReadWriteLock`；写锁覆盖"改内存 + 落盘"全过程。
- **ID 生成**：`AtomicLong`，启动时以文件内 max(id) 初始化；格式建议 Long 自增（与达梦 BIGINT 主键天然兼容）。
- **seed 数据**：`data/seed/*.json` 首次启动自动导入（文件不存在时），用于初始管理员账号与演示数据。
- **字段演进**：Jackson 反序列化 `@JsonIgnoreProperties(ignoreUnknown = true)` + 缺省值兜底；这正是"前期功能频繁调整时文件存储更容易改"的落点——直接改 JSON 文件即可，不用迁移脚本。

### 5.3 一期限制（必须知悉，文档与代码注释同步声明）

- 无跨实体事务：涉及多实体一致性的操作由 Service 顺序调用并补偿（失败回滚已完成的内存变更）。
- 无并发实例：一期后端单实例部署，不支持水平扩缩容（文件存储不可共享）。
- 无复杂查询能力：`findByCondition` 只支持等值 + 预定义范围条件；模糊/组合查询在 Service 内存过滤（数据量小，可行）。

### 5.4 二期：达梦 DM8 对接

| 项 | 方案 |
|---|---|
| 数据库 | 达梦 DM8（服务端），建议初始化实例时选择兼容模式（Oracle 或 MySQL 兼容，由 DBA 按运维习惯定，**一旦选定不可中途切换**） |
| 驱动 | `com.dameng:DmJdbcDriver18:8.1.3.x`（Maven 中央仓库有） |
| 连接池 | HikariCP（Spring Boot 默认），连接参数由 DBA 提供 |
| ORM | MyBatis-Plus 3.5.x，`DbType.DM` 方言，分页插件原生支持达梦 |
| 建表 | `domain/` 对象 → 表结构（字段、类型、主键一一对应），SQL 脚本人工维护进 `db/migration/`（达梦与 Flyway 社区版兼容性需在二期启动时验证，不通过则用脚本目录 + 启动校验版本表的轻量方案） |
| 切换方式 | 新增 `storage/dm/DmRepositoryImpl`（BaseMapper 适配 EntityRepository 接口），`application-prod.yml` 按 profile 激活；**Service / Controller / DTO 零改动** |
| 数据迁移 | 一期 JSON → 达梦：写一次性迁移命令（读取 JSON 文件批量 insert），随二期上线执行 |

## 6. 接口设计规范（与前端现状逐条对齐）

> 以下契约**前端已固定**，后端按此实现，字段名大小写严格一致（前端 TS 类型区分大小写）。

### 6.1 统一响应体

```json
{ "code": 200, "msg": "success", "data": { } }
```

- `code`：与前端 `ApiStatus` 枚举一致：200 成功、400 业务错误、401 未授权、403 禁止、404 不存在、500 服务器错误。
- `code === 200` 才算成功；`code === 401` 时前端**自动登出并跳登录页**（响应拦截器已实现），不要用 401 表示"权限不足"——权限不足用 403。
- 业务失败统一 HTTP 200 + `code: 400` + `msg` 可读文案（前端已全局弹出 `msg`），避免前端走 HTTP 错误重试逻辑（408/5xx 会自动重试 3 次）。

### 6.2 分页契约

请求（GET query 或 POST body）：

```
current=1&size=10          # 页码从 1 开始；另附各业务筛选字段
```

响应 `data`：

```json
{ "records": [], "current": 1, "size": 10, "total": 86 }
```

前端 `useTable` hooks 默认按此结构解析，**不要**用 `list/pageNo/pageNum/rows` 等别名。

### 6.3 鉴权契约

| 项 | 约定 |
|---|---|
| 登录 | `POST /api/auth/login`，body `{ "userName": "", "password": "" }` → `data: { "token": "", "refreshToken": "" }` |
| 用户信息 | `GET /api/user/info` → `data: { "buttons": ["add","edit",...], "roles": ["R_SUPER",...], "userId": 1, "userName": "", "email": "", "avatar": "" }` |
| 携带方式 | 前端把 token **原样**放入 `Authorization` 请求头（无 `Bearer ` 前缀），后端过滤器需兼容 `Authorization: <token>` 与 `Authorization: Bearer <token>` 两种取值 |
| 失效 | 返回 `code: 401`（body 或 HTTP 状态均可，前端两者都处理） |
| 一期 token | 内存/UUID + 登出即失效即可；二期引入 Redis 后升级为服务端会话。不引入 JWT（吊销麻烦，内网系统无必要） |

`buttons` 为按钮级权限编码（前端 `v-auth` 指令消费），`roles` 为角色编码（如 `R_SUPER`）。权限模型：一期静态配置在用户 JSON 数据里，二期建库后做管理页面。

### 6.4 RESTful 风格与 URL 规范

```
GET    /api/<module>/<entity>/page        # 分页查询（也可 GET /api/<module>/<entity> 带分页参数）
GET    /api/<module>/<entity>/{id}        # 详情
POST   /api/<module>/<entity>             # 新增（body 为 DTO）
PUT    /api/<module>/<entity>             # 修改（body 含 id）
DELETE  /api/<module>/<entity>/{id}       # 删除
POST   /api/<module>/<entity>/batch-delete # 批量删除（body: { ids: [] }）
```

- 模块名小写中划线（如 `/api/system/user/page`）。
- 新增/修改入参统一一个 DTO（含 id，新增时 id 为空），减少接口数量。
- 前端 `request` 工具的 POST/PUT 把 `params` 自动移入 body，无需区分传参方式。

### 6.5 菜单接口（仅 backend 路由模式需要，二期可选）

`GET /api/v3/system/menus` → `data: AppRouteRecord[]`，结构与前端 `src/router/modules/*.ts` 导出的对象一致：

```json
{
  "path": "/demo", "name": "Demo", "component": "/index/index",
  "meta": { "title": "menus.demo.title", "icon": "ri:flask-line" },
  "children": [ { "path": "user", "name": "DemoUser", "component": "/demo/user/index",
    "meta": { "title": "menus.demo.user", "icon": "ri:user-settings-line", "keepAlive": true } } ]
}
```

`meta.title` 填的是 **i18n key**（前端翻译），`component` 是 `src/views` 下的路径映射。一期 frontend 模式下该接口不用实现。

### 6.6 接口文档与 Mock

- 后端 SpringDoc UI（`/swagger-ui.html`）作为联调期唯一真源。
- 联调前后端可并行：前端沿用现有 Mock 思路（`src/api/` 内本地函数），接口就绪后按 6.1/6.2 契约切换 `request` 调用。

## 7. 安全设计（一期最低要求）

- 密码存储：BCrypt（spring-security-crypto 的 `BCryptPasswordEncoder`，不引入完整 Spring Security 过滤链，鉴权用轻量 Filter + HandlerInterceptor）。
- 登录防爆破：账号维度失败计数 + 锁定（一期内存实现，二期 Redis）。
- XSS：入参统一 HTML 转义（自定义 Jackson 反序列化器或 Filter）；富文本字段白名单放行。
- CORS：开发走 Vite 代理、生产走 Nginx 同域反代，均无跨域；后端默认关 CORS，需要直连时再按环境白名单开启。
- 越权：所有接口校验登录态；写操作校验数据归属（防水平越权，Service 层按 id 校验 owner）。
- 敏感字段（密码等）DTO 出参一律不返回。

## 10. 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| JSON 存储丢最后一次写（进程被 kill） | 数据少量回退 | 原子写 + 建议低峰期定期备份 `data/` 目录；重要写操作后日志留痕 |
| 一期无事务，多实体操作不一致 | 数据脏 | Service 层顺序变更 + 补偿；涉及一致性的功能在二期优先入库 |
| Domain 字段设计随意，二期建表返工 | 迁移成本 | Domain 强约束：类型用 Long/String/Integer/BigDecimal/LocalDateTime，禁用嵌套 Map；关联用 id 引用不用嵌套对象 |
| 达梦方言/工具链兼容性问题 | 二期进度 | DbType.DM 为 MyBatis-Plus 官方支持项；Flyway 兼容性二期首周做专项验证 |
| 前端误改框架层文件破坏工程 | 交付质量 | 工程根 `AGENTS.md` 已强制（**跨工具生效，随工程目录走**）；人工 code review 对照其第 5 节禁改清单 |

## 附录 A：前端已固定的契约速查（后端开发必读）

| 项 | 值 |
|---|---|
| 响应体 | `{ code, msg, data }`，成功 `code=200` |
| 401 语义 | 未登录/登录失效，前端自动登出；权限不足用 403 |
| 分页请求 | `current`（从 1 起）/ `size` |
| 分页响应 | `records / current / size / total` |
| 鉴权头 | `Authorization: <token>`（无 Bearer 前缀，后端两种都要兼容） |
| 登录 | `POST /api/auth/login` → `{ token, refreshToken }` |
| 用户信息 | `GET /api/user/info` → `{ buttons, roles, userId, userName, email, avatar }` |
| URL 前缀 | 所有接口 `/api` 开头（Vite 代理与 Nginx 反代按此前缀） |
| Content-Type | `application/json`（前端自动设置并序列化） |
