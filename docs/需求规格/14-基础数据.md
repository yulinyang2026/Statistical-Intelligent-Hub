> 版本：v1.0
> 日期：2026-09-09
> 适用范围：本系统（单租户 Web 管理系统，组织/人员规模约百级数据量）
> 文档性质：独立需求文档，不与「用户与组织机构管理需求文档」共用

---

## 1. 背景与目标

管理系统中存在大量「可维护的基础数据 / 枚举字典」，例如：

- **项目状态**：在建、已签约、运维、完成
- **归属产品**：部门统计、国资监管、轻量级统计、统一报表、业务组件库
- **模块分类**：BSP 产品、组件、其他

这些数据的共同特征是：

1. 取值集合经常随业务调整（新增状态、改显示名、加属性）。
2. 取值项可能携带额外字段（如项目状态要带颜色、是否终态）。
3. 业务表需要稳定地引用这些值。
4. 期望由运维/管理员在后台**自助维护**，而不是每次改代码、改库表。

### 1.1 目标

- **可新增字典**：系统运行时能动态创建一类新的基础数据（如新增「合同类型」字典）。
- **可新增字段**：每个字典的字段结构可运行时扩展（如给「项目状态」增加 `color`、`is_terminal` 字段）。
- **可新增枚举数据**：每个字典下能随时增删枚举项（如新增「验收中」状态）。
- **引用稳定**：业务表引用字典项不因改名、排序变化而断裂。

## 2. 术语

| 术语 | 说明 |
| --- | --- |
| 字典 / 基础数据 | 一类可维护的枚举集合，对应一个业务维度（如「项目状态」）。 |
| 字典项 / 枚举值 | 字典下的一个具体取值（如「在建」）。 |
| 字典字段 | 字典项中每个取值可携带的附加属性（如 `color`、`is_terminal`）。 |
| 内置字典 | 系统初始化即存在、且被业务强依赖、不可删除的字典（如项目状态）。 |
| 自定义字典 | 由管理员在运行中创建的字典，可删除。 |
| code | 字典与字典项的稳定引用键（字符串编码），命名如 `project_status` / `IN_PROGRESS`。 |

## 3. 设计原则

1. **元数据驱动 + JSON 扩展**：字典的「结构」与「数据」分开存。字典定义（`dict`）+ 字段定义（`dict_field`）描述结构，枚举数据（`dict_item.ext` 的 JSON）存放各字段值。不在运行时建物理表。
2. **引用用 code，不用 id/显示名**：业务表只存 `字典 code + 字典项 code`，改名、调序都不影响业务引用。
3. **轻量优先**：百级数据量，单表 + 普通索引即可；不做分表、不做复杂缓存框架，全量缓存内存即可。
4. **逻辑删除 + 审计**：字典与字典项停用不物理删除；变更动作统一进操作审计日志（沿用系统既有 `operation_log`）。
5. **内置字典锁**：系统强依赖的字典禁止删除，仅开放停用与字段/数据维护。

## 4. 功能需求

### 4.1 字典定义管理

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| DICT-01 | 字典列表 | 分页展示所有字典：编码、名称、描述、字段数、枚举项数、状态、内置/自定义。支持按名称/编码/状态筛选。 |
| DICT-02 | 新增字典 | 录入编码（唯一、小写蛇形）、名称、描述，状态默认启用。自动携带默认字段 `code`（值编码）、`name`（显示名）。 |
| DICT-03 | 编辑字典 | 修改名称、描述、排序；编码不可改。 |
| DICT-04 | 停用 / 启用字典 | 停用后该字典不出现在业务下拉选择中，但已存业务数据仍保留编码引用。 |
| DICT-05 | 删除字典 | 仅自定义字典可删；删除前校验无业务引用、无启用中的字典项（见 DICT-13）。内置字典不可删，仅可停用。 |

### 4.2 字典字段管理

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| DICT-06 | 字段列表 | 展示某字典下的字段：字段编码、名称、类型、是否必填、是否唯一、排序、默认值、可选项。 |
| DICT-07 | 新增字段 | 录入字段编码、名称、类型（string/int/date/enum/bool）、是否必填、是否唯一、排序、默认值、可选项（enum 类型时）。新增字段后，已有字典项在该字段上值为 null，按 `default_value` 兜底显示，不影响老数据。 |
| DICT-08 | 编辑字段 | 修改名称、类型约束、必填/唯一、默认值、可选项；字段编码不可改（改编码等同破坏历史数据映射）。 |
| DICT-09 | 停用 / 删除字段 | 停用后表单不再展示、校验跳过；删除字段时同步清理 `dict_item.ext` 中该键。建议默认停用而非删除，保留历史值。 |
| DICT-10 | 字段类型约束 | 保存字典项时按字段类型校验（int 转整、date 校验格式、enum 必须在可选项内、bool 取真假）。 |

## 6. 业务表如何引用字典

**原则：业务表存 `字典 code + 字典项 code`，不存显示名、不存字典项 id。**

示例——项目表引用项目状态：

```sql
CREATE TABLE project (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  name          VARCHAR(128),
  status_code   VARCHAR(64)   -- 引用 dict_item.code，如 'IN_PROGRESS'
  -- 如需列表直接展示，可冗余 status_name VARCHAR(128) 便于展示，但权威引用永远是 status_code
);
```

展示时：

```
显示名 = 查 dict(code='project_status') 下 item(code=status_code).name
色块   = 查 item.ext.color
```

改名场景：管理员把「在建」改为「建设中」，只改 `dict_item.name`，所有历史项目记录 `status_code='IN_PROGRESS'` 不变，显示名自动更新。

## 7. 规则与约束

1. **应用层校验**（JSON 不保证结构）：保存 `dict_item` 时按 `dict_field` 逐字段校验——必填、类型、字典内唯一（`is_unique`）、enum 取值在 `options` 内。
2. **热字段索引**：若某自定义字段需频繁筛选/分组（如按 `product_belong` 统计），用 MySQL **生成列 + 索引**把 JSON 键物化为列：
   ```sql
   ALTER TABLE dict_item
     ADD COLUMN product_code VARCHAR(64) AS (ext->>'$.product_code') STORED;
   CREATE INDEX idx_product ON dict_item(product_code);
   ```
   百级数据下大多数场景直接 `JSON_EXTRACT` 也足够，不必强求。
3. **内置字典锁定**：`is_builtin=1` 的字典禁止删除（DICT-05），仅可停用。
4. **字段编码不可改**：改 `field_code` 会破坏 `dict_item.ext` 的键映射，等同数据损坏，禁止（DICT-08）。
5. **字典项 code 不可改**：改名只改 `name`（DICT-13）。
6. **删除保护**：删除字典项/字典前，校验其 code 是否仍被业务表引用（DICT-16），被引用则拦截并提示引用位置。
7. **缓存策略**：字典为高频只读数据，全量缓存到内存（或 Redis），变更时按 `dict.code` 失效。百级数据量下全量加载无压力。
8. **审计一致**：字典的增/删/改、字段变更、枚举项变更统一写入操作审计日志 `operation_log`（`target_type='dict'` / `'dict_field'` / `'dict_item'`），沿用系统既有审计规范。

## 8. 非功能性需求

| 项 | 要求 |
| --- | --- |
| 数据规模 | 单表百级 ~ 千级数据，无需分表 |
| 性能 | 字典查询命中缓存；首次加载与变更失效后可接受短暂回源 |
| 并发 | 后台管理并发低，普通行锁即可 |
| 安全 | 字典维护需具备相应功能权限（并入既有 RBAC）；服务端校验所有输入 |
| 审计 | 所有写操作留痕，含操作人、时间、前后值摘要 |
| 兼容性 | 业务表引用通过 code，字典结构变更对业务透明 |

## 9. 待确认边界

1. **内置字典清单**：哪些字典随系统初始化且锁定不可删？是否仅「项目状态/归属产品/模块分类」三项，还是有更多？
2. **字段类型范围**：`enum` 之外的 `date`、`int`、`bool` 是否本期就需要，还是先只支持 `string` + `enum`？
3. **删除字段策略**：字段默认「停用」还是允许「物理删除并清理 ext」？建议默认停用。
4. **批量导入**：是否需要 Excel/CSV 批量导入（DICT-15），还是纯手工录入？
5. **引用自动登记**：业务表与字典的引用关系是否需要一张元数据表显式登记（便于 DICT-16 查询），还是由开发约定、删除时人工确认？
6. **字典项图标/颜色**：扩展字段（如 `color`）是否需要在下拉、列表、报表中真实渲染，还是仅作数据存储？
