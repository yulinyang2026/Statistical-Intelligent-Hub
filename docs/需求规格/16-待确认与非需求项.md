# 16 待确认需求与非需求项

> 本文件记录**尚未确认**的需求与**不属于需求**的工程事项。
> 待确认项经用户拍板后，应移入对应模块文件并删除本文件中的条目。
> **第 2 节「对话需求登记」是用户需求的强制入口**：用户每次提出的需求/改动意向必须先在此登记，定稿后归位（流程见 `99-变更记录与文档约定.md` 第 3.6 节）。

## 1. 模块定位

区分"还没定"与"不是需求"，避免 AI 开发时误把待确认项当既定需求实现，或把环境问题当缺陷排查。同时作为用户对话需求的**强制登记入口**，保证每条需求可追溯（流程见 `99-变更记录与文档约定.md` 第 3.6 节）。

## 5. 已知技术边界（非缺陷）

| 边界                     | 说明                                                                                                        |
| ------------------------ | ----------------------------------------------------------------------------------------------------------- |
| 主题色覆盖为近似值        | 仅覆盖 Arco `--primary-6` / `--arcoblue-6`，主按钮/链接/选中态跟随，部分组件次级色可能不完全一致             |
| 菜单布局切换需刷新        | `menuLayout` 在布局加载时读取，切换保存后需刷新页面生效                                                     |
| 计划完成时间双轨并存      | 表单为「第几周」，周计划拖拽写「具体日期」；展示时 `planDate` 优先                                           |
| 数据仓储为 JSON 文件      | 启动全量载入内存、写操作整文件覆盖，数据量大时存在性能与并发写风险；生产环境需替换为数据库（见技术方案文档） |
