# 08a 任务管理 · 看板视图详细需求

> 本文是对 `08-任务管理.md` 第 4.3 节（进度看板与看板视图）的**展开细化**，依据当前实现逐项整理。
> 覆盖范围：任务管理页「看板视图」的完整交互逻辑——分组维度单选/多选、内容筛选、列生成规则、卡片构成、拖拽写回、工时内联编辑。
> 同一组件（KanbanBoard）也被模块/专题/项目详情页「进度看板」复用，其受限形态见文末第 10 节。

---

## 1. 模块定位

### 1.1 职责

任务管理页的第二种视图形态：以**看板列**呈现任务，支持按 5 个维度自由分组（含多选交叉列）、按维度值筛选、拖拽卡片变更字段、双击编辑工时。

### 1.2 边界

- 与列表视图**共享同一份数据与筛选范围**（看板使用当前权限与筛选下查得的全部任务，**不受分页影响**）。
- 不负责任务增删改的表单交互（新增/编辑仍走弹窗表单，见 08 号文件）。
- 子系统维度**只读分组**，不支持拖拽写回。

| 区域     | 内容                                                                                                                         |
| -------- | ---------------------------------------------------------------------------------------------------------------------------- |

- 组员：`仅显示分配给我的任务 · 待办口径：状态 ≠ 已完成`

## 3. 分组维度（核心逻辑）

### 3.1 维度定义

| # | 维度 key    | 显示名   | 取值字段          | 固定顺序                               | 可拖拽写回 |
| - | ----------- | -------- | ----------------- | -------------------------------------- | :--------: |
| 1 | `status`    | 任务状态 | `status`          | 待处理 → 进行中 → 已完成 → 受阻         |     ✅     |
| 2 | `priority`  | 优先级   | `priority`        | 高 → 中 → 低                           |     ✅     |
| 3 | `assignee`  | 执行人   | `assignee`        | 无（按任务集出现顺序）                  |     ✅     |
| 4 | `group`     | 归属小组 | `group`           | 无                                     |     ✅     |
| 5 | `deadline`  | 截止月份 | `deadline`        | 无                                     |     ✅     |

> **下线（2026-09-10，V6.23，来源：用户需求「分组维度去掉子系统维度」，问答确认：分组 Tag 与内容筛选下拉都移除）**：原第 6 维度 `subsystem`（子系统）已从看板视图移除——分组维度 Tag 与内容筛选下拉均不再展示；卡片「补充信息」仍展示子系统名称（恒显示）。后端 `subsystemId` 字段保留兼容。

### 3.2 选中规则

- **默认选中**：`任务状态`（单选）。
- 点击未选中的维度 Tag → **追加**到已选序列**末尾**；点击已选中的 → 从序列**移除**。
- **至少保留一个维度**：尝试取消最后一个维度时，Toast 警告「至少保留一个分组维度」，操作被拒绝。
- 已选维度高亮显示（蓝色 Tag），未选为灰色。
- **选中顺序有意义**：第一个选中的维度即**主维度**，决定拖拽写回的字段与交叉列的排序基准。

### 3.3 单选效果（仅勾选一个维度）

按该维度的取值分列，一列一个值：

| 主维度   | 列生成规则                                                                                     |
| -------- | ---------------------------------------------------------------------------------------------- |
| 任务状态 | **四列固定**：待处理 / 进行中 / 已完成 / 受阻，**无任务也保留空列**（列内显示「暂无任务」）      |
| 优先级   | 高 / 中 / 低，**只显示有任务的列**                                                              |
| 执行人   | 按当前任务集中实际出现的执行人分列（出现顺序）                                                    |
| 归属小组 | 按实际出现的小组分列                                                                              |
| 截止月份 | 按实际出现的月份分列（如 2026-02、2026-03…）                                                      |
| 子系统   | 按实际出现的子系统名称分列                                                                        |

### 3.4 多选效果（勾选两个及以上维度 → 交叉列）

- **列名 = 各选中维度的取值按选中顺序用 ` · ` 连接**。
  例：依次勾选「任务状态 + 优先级」→ 生成 `待处理 · 高`、`待处理 · 中`、`进行中 · 高`、`已完成 · 低`、`受阻 · 中` …
- **只生成有任务的组合列**，空组合不出现。
- **列排序**：若主维度（第一个维度）有固定顺序（状态/优先级），交叉列按主维度顺序优先排列；否则按任务集中首次出现顺序。
- 组合内取值为空时显示 `—`（如任务无归属小组 → `进行中 · — `）。
- **多选会显著增加列数**（理论列数 = 各维度取值数的笛卡尔积中有任务的组合数），列区横向滚动查看。

### 3.5 主维度与拖拽的关系

- **主维度 = 已选维度序列的第一个**。
- 提示文案随状态变化：可编辑时显示「拖动卡片可变更主维度（第一个维度）」；只读时显示「支持多选，组合生成交叉列」。

## 4. 内容筛选（维度值过滤）

- 每个维度一个下拉选择器，占位符 `XX·全部`（如「执行人·全部」）。
- **候选值来源**：当前任务集中该字段实际出现的值去重；状态、优先级按固定顺序排列，其余按出现顺序。
- **多维度筛选为 AND 组合**：同时选「执行人=李泽昆」+「截止月份=2026-03」→ 只显示同时满足的卡片。
- 筛选**只过滤卡片，不改变列结构**（列仍按分组维度生成，空列保留状态列特性）。
- 任一筛选生效时：
  - 出现「清除筛选」按钮，一键清空全部筛选（含年月过滤，若展示）。
  - 提示文案变为 `已筛选，剩余 N 个任务`。
- 无筛选时提示 `按维度内具体内容过滤，如执行人、截止月份`。

## 5. 看板列

| 元素     | 规则                                                                                                                                |
| -------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 列头     | 色块（10×10 圆角方块）+ 列名（13px 加粗）+ 数量徽标（该列卡片数）                                                                     |
| 色块颜色 | 主维度为**任务状态**：待处理 `#86909c` / 进行中 `#5D87FF` / 已完成 `#67C23A` / 受阻 `#F56C6C`；主维度为**优先级**：高 `#F56C6C` / 中 `#E6A23C` / 低 `#909399`；**其余主维度统一** `#5D87FF`（交叉列取第一段判断） |
| 空列     | 仅「任务状态」单选时保留空列，列内显示「暂无任务」                                                                                      |
| 溢出     | 列数超出视口宽度时，列区横向滚动                                                                                                        |
| 列内排序 | **树形规则**：父任务在前，其子任务紧跟其后并缩进；**孤儿子任务**（父任务不在本列）自动追加到列尾，不丢失                                |

## 6. 任务卡片

> **2026-09-10 修订（用户需求「卡片高度减半」，布局由 AI 规划）**：由原五行结构紧凑化为**三行结构**，高度约为原一半。

| 行             | 内容                                                                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ① 标题行       | 任务名称（13px 中等字重，超长省略号）+ 说明图标（悬停气泡显示说明/名称）+ **子任务计数徽标** `+N`（有子任务时显示，悬浮提示「含 N 个子任务」）               |
| ② 元信息行     | 优先级 Tag（高=红 / 中=黄 / 低=灰）+ 执行人姓名（超长省略号）+ 计划完成（`planDate` 日期优先，否则 `第N周`，品牌色显示，均无则不显示）+ 预计工时 `Nh`（**双击原位编辑**） |
| ③ 子任务与补充信息行 | 仅子任务显示：`↳ 子任务 · 父：{父任务标题}`（品牌色小字）；+ **补充信息**（自动显示当前分组未覆盖的维度：截止月份 · 执行人 · 归属小组 · 子系统，分组中已作为维度的项不再显示；子系统已从分组维度下线，**恒显示**）；两者均无时本行不渲染 |

**卡片外观（2026-09-11 修订，用户需求「边框别弄成黑的，换个和主题颜色协调的配置，且要凸显卡片」）**：卡片边框由 Tailwind 默认 `currentColor`（渲染为黑/深色）改为**主题色描边** `border-theme/30`（跟随系统主题色，暗色模式自动适配），并加**轻阴影** `shadow-xs`、圆角 `rounded-md`——与列容器 `.art-card` 的中性描边区分开，卡片感更明确。未新增 `@keyframes`/自定义 transition，未硬编码色值（走 `--color-theme` 原子类）。

**状态样式**：`已完成` 状态的卡片整体 55% 透明度（视觉弱化，仍可拖拽移出）。

**卡片紧凑化**：小内边距（8px）、11~13px 字号、紧凑行距与卡间距，同屏容纳更多卡片（FR-V5-018）。整卡按深度缩进（每级 14px，任务树仅两级）。

## 7. 交互行为

### 7.1 双击编辑预计工时

1. 双击卡片上的 `Nh` 区域 → 原位变为数字输入框（small 尺寸，最小 0）。
2. **失焦或回车**提交：值有变化时 `PATCH /api/tasks/:id { field: 'hours', value }`（2026-09-10 确认沿用 PATCH 单字段写回，原 PUT 契约废弃），Toast「工时已更新」并刷新看板。
3. 只读角色不可触发编辑。

### 7.2 拖拽变更字段

| 项           | 规则                                                                                                                                  |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------- |
| 前置条件     | 当前用户非只读 **且** 主维度可拖拽（子系统维度除外）                                                                                       |
| 拖拽方式     | SortableJS，卡片可在**列间**拖动，动画 150ms                                                                                             |
| 落点解析     | 目标列名若为交叉列（含 ` · `），**取第一段**作为写回值（即按主维度写回）                                                                     |
| 写回字段     | 主维度对应字段：`status` / `priority` / `assignee` / `group` / `deadline`                                                                  |
| 同列移动     | 从某列拖回同列且位置未变 → 不触发请求                                                                                                      |
| 成功后       | Toast「已变更为『{value}』」→ 重新加载任务 → 看板按新值重新分列（卡片可能移动到新列）                                                       |
| 服务端行为   | `PATCH /api/tasks/:id`：校验 `canEditTask` → 校验字段在允许清单 → 写入 → **写操作日志**（记录旧值→新值）→ **触发模块/专题状态自动流转**         |
| 值未变化     | 服务端返回 `changed: false`，不写日志                                                                                                       |

### 7.3 看板与列表视图的关系

- 顶部单选按钮组切换「列表视图 / 看板视图」，**共享同一份任务数据**（看板取当前筛选与权限范围的全部结果，不受列表分页限制）。
- 「新增任务」按钮两个视图下均显示，点击打开任务弹窗表单。
- 列表视图的筛选条件（名称/状态/归属等）**不影响看板视图**——看板有自己的内容筛选体系，两套筛选相互独立。

## 8. 数据范围与权限

| 角色       | 可见任务                     | 拖拽 | 双击编辑工时 |
| ---------- | ---------------------------- | :--: | :----------: |
| 系统管理员 | 全部                         |  ✅  |      ✅      |
| 部门经理   | 权限人员（本人+下属）的任务   |  ✅  |      ✅      |
| 组长       | 权限人员（本人+下属）的任务   |  ✅  |      ✅      |
| 组员       | **仅分配给自己的**           |  ✅  |      ✅      |
| 只读查看者 | 全部（只读提示条）           |  ❌  |      ❌      |

- 只读角色进入页面顶部显示提示条；拖拽与工时编辑均不可用。
- 服务端对每次写回做 `canEditTask` 二次校验，前端拦截不可靠时后端兜底。

## 9. 接口清单

| 方法  | 路径                 | 请求体 / 参数                                                        | 说明                                                         | 所需权限点 |
| ----- | -------------------- | -------------------------------------------------------------------- | ------------------------------------------------------------ | ---------- |
| GET   | `/api/tasks`         | query：`current/size` 及各筛选字段（`size<=0` = 全量）                 | 看板数据源（当前范围**全量**任务，含 `subsystemName`、`childCount`；无 `task.view-all` 时仅返回 assignee = 自己的任务） | `task.view` |
| GET   | `/api/tasks/options` | —                                                                    | 筛选候选值（执行人、小组、月份、状态、优先级、子系统等）         | `task.view` |
| PATCH | `/api/tasks/:id`     | `{ field, value }`，field ∈ `status/priority/assignee/group/deadline/planDate/hours` | **拖拽写回 + 工时编辑**（2026-09-10 起工时沿用 PATCH）；校验 `task.edit` 权限与字段白名单（无 `task.view-all` 时仅限分配给自己的任务，403）；值未变化返回 `{ changed: false }` 不写日志；变更时写操作日志（旧值→新值）；触发状态流转 | `task.edit` |

## 10. 复用形态：对象详情页进度看板

同一组件在模块/专题/项目详情页「进度看板」Tab 中以**受限形态**复用：

| 差异点       | 任务管理看板视图     | 详情页进度看板                       |
| ------------ | -------------------- | ------------------------------------ |
| 分组维度     | 5 维度自由多选       | **固定按任务状态分列**（不可改）      |
| 内容筛选     | 有                   | 无                                   |
| 年月过滤     | 无                   | 有（按**计划完成时间所属月份**过滤，与新建任务同行；2026-09-10 措辞修正）  |
| 列固定       | 随维度               | 四列固定，无任务也保留               |
| 拖拽         | 主维度写回           | 仅状态列间拖拽（写 `status`）         |
| 任务范围     | 全局任务（按权限）   | 该对象范围内的任务（含挂靠项目任务）  |

## 11. 验收标准

- [ ] 默认进入看板视图为「任务状态」单维分组，四列固定显示（含空列）
- [ ] 点击维度 Tag 追加/移除维度，已选高亮；取消最后一个维度被拒绝并提示
- [ ] 勾选「任务状态 + 优先级」生成 `状态 · 优先级` 交叉列，按状态顺序排列，空组合不出现
- [ ] 主维度（第一个勾选）决定拖拽写回字段；交叉列拖拽取列名第一段写回
- [ ] 拖拽成功后 Toast 提示、看板刷新、操作日志记录旧值→新值、模块/专题状态自动流转触发
- [ ] 内容筛选多维度 AND 生效，显示剩余数量，可一键清除
- [ ] 卡片补充信息自动隐藏已被分组维度覆盖的项
- [ ] 卡片边框为主题色系描边（非黑色），带轻阴影，与列容器可区分
- [ ] 子任务缩进显示并标注父任务名；孤儿子任务追加列尾
- [ ] 双击工时内联编辑，失焦/回车保存，只读角色不可触发
- [ ] 已完成卡片半透明弱化
- [ ] 组员看板仅显示自己的任务；只读角色看到提示条且不可拖拽
- [ ] 列数超出视口时横向滚动
