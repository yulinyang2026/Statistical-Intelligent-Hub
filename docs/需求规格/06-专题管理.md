# 06 专题管理

## 1. 模块定位

### 1.1 职责

管理**阶段性特有事项**（专题）全生命周期：列表、筛选、增删改、导入导出、详情页、待办任务数、状态自动流转。

### 1.2 边界

- 与模块管理**共用一套交互与状态字典**，区别在于业务定位。
- **不设「模块分类」「归属产品」字段**（专题无此属性）。
- 其余能力与模块管理对等。

## 2. 依赖关系

| 方向     | 对象                                                                          |
| -------- | ----------------------------------------------------------------------------- |
| 依赖     | `02-数据模型`、`14-基础数据`（模块/专题状态字典）、`12-用户与组织`             |

## 3. 数据契约

**主实体 Topic**

| 字段           | 类型     | 必填 | 说明                                    |
| -------------- | -------- | :--: | --------------------------------------- |
| id             | string   |  —   | 主键，前缀 `tp`                         |
| name           | string   |  √  | 专题名称                                |
| dept           | string   |  √  | 负责部门                                |
| team           | string   |  √  | 负责小组                                |
| owner          | string   |  √  | 专题负责人（存姓名）                    |
| rd[]           | string[] |  —   | 研发负责人（多）                        |
| test           | string   |  —   | 测试负责人                              |
| cost           | string   |  —   | 成本对象                                |
| status         | string   |  √  | 状态（引用「模块/专题状态」字典，自动流转） |
| stakeholders[] | string[] |  —   | 干系人                                  |
| desc           | string   |  —   | 专题描述                                |

> **与模块的差异**：无 `product`、无 `category` 字段。其余一致。

**派生字段**：`todoCount`（**仅直属任务**，挂靠概念 2026-09-11 起移除）、`canEdit`。

**内置数据**：5 个专题——前端性能优化、文档库优化、服务启动性能优化、运维推动、AI事项推动（`tp1`~`tp5`，见 `backend/src/main/resources/seed/topic.json`）。

## 5. 接口清单

| 方法   | 路径                    | 说明                                                  | 所需权限点 |
| ------ | ----------------------- | ----------------------------------------------------- | ---------- |
| GET    | `/api/topics`           | 列表，支持 `kw/dept/team/owner/status/scope/page/size` | `topic.view` |
| GET    | `/api/topics/:id`       | 详情（含统计概览、挂靠项目、成员）                     | `topic.view` |
| POST   | `/api/topics`           | 新增                                                  | `topic.edit` |
| PUT    | `/api/topics/:id`       | 编辑                                                  | `topic.edit` |
| DELETE | `/api/topics/:id`       | 删除（级联提示任务数）                                 | `topic.edit` |
| GET    | `/api/export/topics`    | 导出 Excel(.xlsx)                                     | `topic.view` |
| POST   | `/api/import/topics`    | 导入 Excel(.xlsx)                                     | `topic.edit` |

> 路径**统一用复数** `/api/topics`（后端兼容单数 `/api/topic`，勿改回）。
> 补充（2026-09-11 实现）：列表/详情均带 `GET /api/topics/options`（状态字典 + 部门/小组组织树 + 现有负责人候选值）；`scope=mine` 表示仅本人负责的专题；`size=0` 表示全量（导出复用）。Excel 路径 `/api/export/topics`、`/api/import/topics`（单复数兼容，`?token=` 鉴权）。
