# 需求规格总索引与开发指南

> 本目录是 `需求规格说明书_V6.0.md` 的**模块化拆分版**，面向 AI 按模块独立开发。
> 人读完整版仍为同目录的 `需求规格说明书_V6.0.md`（合订本，内容同源）。
> 若两者出现不一致，**以本目录的模块文件为准**，并回补合订本。

## 1. 如何使用本目录


| 你的目的                     | 读哪些文件                                            |
| ---------------------------- | ----------------------------------------------------- |
| 了解系统全貌、术语、角色权限 | `01-概述与公共约定.md`                                |
| 了解数据实体、字段、枚举     | `02-数据模型.md`                                      |
| 开发某个具体模块             | 该模块文件 +`02-数据模型.md` + `01-概述与公共约定.md` |
| 判断开发顺序与依赖           | 本文件的第 3、4 节                                    |
| 查看历史变更与文档同步规则   | `99-变更记录与文档约定.md`                            |

**AI 开发单个模块时的最小上下文**：`01` + `02` + 该模块文件，共 3 份。

**依赖说明**（箭头由被依赖方指向依赖方）：

- **02 数据模型**是根，无上游。
- **14 基础数据**为 05/06/07 提供字典值（归属产品、项目状态、模块专题状态、模块分类）。
- **12 用户组织 / 13 角色权限**为所有模块提供人员字段与权限判定。
- **05 模块 / 06 专题**曾可被 **07 项目** 挂靠（项目 `belongType + belongId`）——**2026-09-11 起挂靠概念移除**，字段保留但不再写入与展示。
- **08 任务**归属 模块/专题/项目 三者之一，可关联子系统。
- **09 周计划 / 04 数据看板**均为**只读聚合 + 写回**的上层应用，强依赖 08。
- **10 文档**挂在对象（模块/专题/项目）下，随对象生命周期（2026-09-10 实现，随 05 落地）。
- **11 成员管理已取消**（2026-09-10 用户确认，不再规划）：成员由对象角色字段（负责人/研发/测试/干系人）+ 任务执行人**自动推导**，见 05 号文档 FR-MOD-007。

## 4. 推荐开发顺序

严格按下述顺序开发可避免"做到一半发现缺依赖"：


| 阶段 | 模块                                      | 产出验收                                       |
| ---- | ----------------------------------------- | ---------------------------------------------- |
| P0   | 02 数据模型                               | 实体与字段定义冻结，枚举字典可维护             |
| P1   | 12 用户组织 → 13 角色权限 → 03 登录鉴权 | 可登录、可按角色看到不同菜单与数据             |
| P2   | 14 基础数据                               | 字典可增删改，被业务表单引用                   |
| P3   | 05 模块 → 06 专题 → 07 项目与子系统     | 三类对象 CRUD、树形子系统、待办数正确          |
| P4   | 08 任务管理                               | 列表树形、看板拖拽、状态自动流转、待办口径一致 |
| P5   | 09 周计划 → 04 数据看板                  | 拖拽写回计划完成日期、看板分布图数据正确       |
| P6   | 10 文档中心（11 成员管理已取消，成员由角色字段自动推导） | Markdown 编辑、对象内文档 Tab                |
| P7   | 15 系统设置与操作日志                     | 主题可配并持久化、关键操作有留痕               |

> 每个阶段开发时，先读对应模块文件的「数据契约」与「接口清单」两节，可独立开工。

## 5. 模块文档模板

每个模块文件遵循统一结构，**AI 读取时可预期**：


| 章节        | 内容                                                                         |
| ----------- | ---------------------------------------------------------------------------- |
| **YAML 头** | `module` / `status` / `depends_on` / `data_entities` / `perm_keys`，机器可读 |
| 1. 模块定位 | 职责（做什么）与边界（不做什么）                                             |
| 2. 依赖关系 | 依赖谁、被谁依赖、涉及哪些数据实体                                           |
| 3. 数据契约 | 本模块主实体字段 + 关联字段                                                  |
| 4. 功能需求 | FR 编号 + 描述 + 优先级                                                      |
| 5. 接口清单 | 方法 / 路径 / 说明 / 所需权限点                                              |
| 6. 权限要求 | 角色 × 操作矩阵                                                             |
| 7. 验收标准 | 可勾选的验收项                                                               |

## 6. 全局技术约定（AI 必读）


| 约定             | 说明                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------- |
| **接口前缀**     | 全部`/api`，RESTful，JSON 收发                                                        |
| **鉴权**         | `Authorization: Bearer <token>`；导出类接口额外支持 `?token=` 查询参数与 `x-token` 头 |
| **权限判定**     | 服务端按**权限点**（见 `02-数据模型.md` 第 4 节）判定，禁止在业务代码里硬编码角色名   |
| **数据范围**     | 默认按「权限人员」（本人 + 监督子树）过滤；清除筛选可见全部，范围外只读。**模块/专题管理例外（2026-09-11）**：仅参与者（负责人/研发/测试）及其上级可见，`module:view-all` / `topic:view-all`（仅系统管理员）豁免 |
| **分页**         | 所有列表默认 50 条/页，可选 50/100/150，分页固定页面右下角，返回`{ list, total }`                          |
| **模块路径**     | 模块/专题接口为**复数** `/api/modules`、`/api/topics`（后端同时兼容单数，勿改回单数） |
| **依赖锁定**     | `vue-router` 必须精确 `4.5.1`，禁止 `^`（规避 Edge 无法最小化缺陷，详见技术方案文档） |
| **状态自动流转** | 仅模块/专题：待办 > 0 → 活跃，= 0 → 非活跃；项目状态人工维护，不自动流转            |
| **待办口径**     | 状态 ≠ 已完成；模块/专题**仅统计直属任务**（挂靠概念 2026-09-11 移除）；**项目统计 = 未挂子系统的直属任务，子系统各计自己的，两者独立**（列表、看板、统计、看板分布图必须一致） |
