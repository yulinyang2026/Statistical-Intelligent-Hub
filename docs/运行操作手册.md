# 运行操作手册（前端 / 后端：启动 · 运行 · 停止）

> 适用工程：日常管理平台（Statistical Intelligent Hub）
> 本手册全部命令于 2026-09-09 在本机实测通过（含登录接口与组织树接口联调验证）。

## 1. 环境要求

| 组件 | 要求 | 本机实测 |
| ---- | ---- | -------- |
| Node.js | ≥ 20.19.0（`frontend/package.json` engines） | v24.14.1 ✓ |
| pnpm | ≥ 8.8.0 | 12.3.4 ✓ |
| JDK | 17+（工程编译目标 Java 17，本机运行 JVM 为 Java 21） | `D:/Wrok/JAVA-21` ✓ |
| Gradle | 8.9（系统安装，**工程无 wrapper**，需自行安装 Gradle） | 8.9 ✓ |

注意：

- 本机 PATH 上的默认 `java` 为 1.8（`java -version` 可见），**直接用 `java -jar` 运行后端需显式使用 Java 17+**（如 `D:\Wrok\JAVA-21\bin\java.exe`）；走 `gradle bootRun` 则不受影响——`backend/gradle.properties` 已通过 `org.gradle.java.home=D:/Wrok/JAVA-21` 锁定 Gradle 运行 JVM。换机器时需同步修改该配置。

## 2. 服务与端口总览

| 服务 | 端口 | 访问地址 | 配置位置 |
| ---- | ---- | -------- | -------- |
| 前端（开发服务器） | 3006 | http://localhost:3006 | `frontend/.env` → `VITE_PORT` |
| 后端（Spring Boot） | 8080 | http://localhost:8080 | `backend/src/main/resources/application.yml` → `server.port` |
| 接口文档（Swagger） | 8080 | http://localhost:8080/swagger-ui.html | 后端运行即可访问 |

## 3. 前端

### 3.1 首次准备

```bash
cd frontend
pnpm install
```

### 3.2 启动开发服务器

```bash
cd frontend
pnpm dev        # = vite --open，自动打开浏览器
```

- 启动成功提示 `VITE v7.3.6 ready in xxx ms`，端口 3006（`host: true` 已开启，局域网可通过 `http://<本机IP>:3006` 访问）。
- 浏览器访问 http://localhost:3006

### 3.3 联调本地后端（重要）

开发环境的 `/api` 请求经 Vite 代理转发，目标地址由 `frontend/.env.development` 的 `VITE_API_PROXY_URL` 决定，**默认指向 Apifox mock 服务器**：

```
VITE_API_PROXY_URL = https://m1.apifoxmock.com/m1/6400575-6097373-default
```

要联调本地后端，把该值改为：

```
VITE_API_PROXY_URL = http://localhost:8080
```

改完**重启 `pnpm dev`** 生效。

### 3.4 停止

- 在运行 `pnpm dev` 的终端按 `Ctrl + C`。
- 若终端已关闭（进程残留）：见第 6 节按端口清理。

### 3.5 构建与预览（生产方式）

```bash
cd frontend
pnpm build      # vue-tsc 类型检查 + vite build，产物在 dist/
pnpm serve      # vite preview 本地预览 dist/ 产物
```

`dist/` 目录可直接交给任意静态服务器（Nginx 等）部署。

## 4. 后端

### 4.1 启动（命令行）

```bash
cd backend
gradle bootRun
```

- 首次启动会下载依赖（已配置阿里云镜像优先）。
- 看到 `Started AdminApplication in x seconds` 即就绪；首次运行且数据文件不存在时，会自动从 `backend/src/main/resources/seed/*.json` 导入种子数据。
- **必须在 `backend/` 目录下启动**：数据目录 `app.data-dir: ./data` 是相对工作目录的，从其他目录启动会找不到数据。

### 4.2 启动（IDEA）

1. IDEA 打开 `backend/` 工程（Gradle 项目）。
2. 运行主类 `com.bsp.admin.AdminApplication`。
3. 检查运行配置的 **Working directory 为 `backend/`**（保证 `./data` 正确解析）。

### 4.3 启动验证

```bash
# 登录接口（admin / 123456，实测返回 code 200 与 token）
curl -X POST http://localhost:8080/api/auth/login \
  -H "Content-Type: application/json" \
  -d '{"userName":"admin","password":"123456"}'

# 带 token 的业务接口（组织树）
curl http://localhost:8080/api/system/org/tree \
  -H "Authorization: Bearer <上一步返回的 token>"
```

### 4.4 停止

- 命令行方式：终端按 `Ctrl + C`（Gradle 守护进程可保留，不影响）。
- IDEA 方式：点击 IDEA 运行面板的停止按钮。
- 进程残留时按第 6 节按端口清理。

### 4.5 打包运行（可选）

```bash
cd backend
gradle bootJar
# 产物：build/libs/bsp-admin-backend-0.1.0-SNAPSHOT.jar
# 运行（必须显式用 Java 17+，且工作目录为 backend/）：
D:/Wrok/JAVA-21/bin/java.exe -jar build/libs/bsp-admin-backend-0.1.0-SNAPSHOT.jar
```

## 5. 登录

- 前端页面 http://localhost:3006 ，手动输入账号密码登录（2026-09-10 起登录页不再提供角色/账号下拉选择，权限由登录账号的角色决定）。
- 种子账号（密码均为 `123456`）：**超级管理员** `admin` / **部门管理员** `zhangwei` / **普通员工** `liuyang`。
- 种子数据中所有账号的初始密码均为 `123456`（seed 中 `SEED:123456` 占位在首次导入时转为 BCrypt 哈希）。
- 连续多次登录失败会临时锁定该账号（防爆破），等待锁定时长过后再试。
- 账号状态为停用的无法登录（`data/system/account.json`、`user.json` 中 `status` 字段）。

### 5.1 如何确认前端确实连上了本地后端

- **看错误文案**：登录报「用户名或密码错误」这类文案本身就来自后端 `AuthService` 的 `BizException`——mock 服务器不会返回该文案，看到它即证明请求已到达后端。
- **看浏览器 DevTools**：F12 → Network → 找到 `login` 请求：
  - Request URL 为 `http://localhost:3006/api/auth/login`（经 Vite 代理转发到 `VITE_API_PROXY_URL`）；
  - Response 是后端 JSON 结构（`code` / `msg` / `data.token`），而非 mock 的假数据。
- **看后端日志**：登录成功/失败时后端控制台会打印登录与审计日志。
- **命令行复核**：`curl -X POST http://localhost:3006/api/auth/login -H "Content-Type: application/json" -d '{"userName":"admin","password":"123456"}'`——返回 `code:200` 与 `token` 即全链路打通。

## 6. 按端口强制停止（Windows）

```bat
:: 查占用端口的进程 PID
netstat -ano | findstr :8080     :: 后端
netstat -ano | findstr :3006     :: 前端

:: 强制结束（把 <PID> 换成上一步查到的值）
taskkill /F /PID <PID>
```

## 7. 常见问题

| 现象 | 原因与处理 |
| ---- | ---------- |
| `gradle bootRun` 报 `Port 8080 was already in use` | 已有后端实例在运行（如 IDEA 中已启动）。按第 6 节找到 8080 的 PID 判断是否为本工程进程：是则停掉旧的，不是则改 `application.yml` 端口（前端代理目标需同步改） |
| 前端接口 404 / 返回 mock 数据 | 检查 `.env.development` 的 `VITE_API_PROXY_URL` 是否指向本地后端，改后需重启 `pnpm dev` |
| 前端端口 3006 被占用 | Vite 会自动顺延端口（3007…），或按第 6 节清理占用进程 |
| 后端启动后数据为空 | 确认启动工作目录为 `backend/`；数据文件被误删时会自动重新导入 seed（现有数据会丢失，谨慎） |
| 重置演示数据 | 停止后端 → 删除 `backend/data/system/` 下的 JSON 文件 → 重启后端（自动重新导入 seed） |
| `java -jar` 报版本错误 | 使用了 PATH 上的 Java 1.8；改用 `D:/Wrok/JAVA-21/bin/java.exe` |
| 登录报「用户名或密码错误」 | 账号停用、密码非 123456（已改过）、或多次失败被临时锁定 |
