核验结论（易踩坑）：
- `src/views/index/index.vue` 是整站布局容器（routesAlias.ts `Layout='/index/index'`），不是首页，删了全站白屏
- `src/mock/json/chinaMap.json` 被核心组件 `art-map-chart` 引用；`src/mock/upgrade/changeLog.ts` 被 `utils/sys/upgrade.ts` ← `App.vue` 引用，二者不可当假数据删

- 动画位置：`styles/core/router-transition.scss`（路由）、`theme-animation.scss`+`theme-change.scss`（主题切换）、`utils/ui/animation.ts`
- 58 个 `Art*` 组件由 unplugin-vue-components 自动注册（名单在 `src/types/import/components.d.ts`）
- `useTableHeight` 未在 `hooks/index.ts` 导出，需从 `@/hooks/core/useTableHeight` 引入
- 路由 hash 模式；`@icons` 别名指向的 `src/assets/icons` 目录实际不存在

工具备注：`directory-tree.txt` 是 UTF-16LE 编码，Read 工具读不了，已转存 `directory-tree-utf8.txt`。

## 编写 AI-GUIDE.md（AI 开发规则）

产出：`AI-GUIDE.md`（项目根目录）。按用户草稿补充真实路径与可运行骨架（列表页 + 表单弹窗），已实测骨架 `vue-tsc` 零错误、`vite build` 通过。

关键实测结论（对二次开发很重要）：
- 项目已改名 `statistical-intelligent-hub`（package.json），非 git 仓库
- 用户已删除全部演示业务页，`src/views/` 仅剩 auth/exception/index/outside/result
- **框架自身有 20 个历史 vue-tsc 类型错误**（art-form 7、art-search-bar 10、http 1、art-table 1、SidebarSubmenu 1），导致 `pnpm build`（含 vue-tsc）必然失败；实际构建用 `vite build` 通过。已写入 AI-GUIDE.md 6.1
- 自动导入边界：`ElMessage` 免 import，但 `ElMessageBox`、`useI18n`、`useTable` 需手写 import；`ArtForm` 模板可用但脚本里取不到类型，ref 用结构化类型声明
- ArtForm 对外暴露 `ref/validate/reset/getOutput`；ArtTable 分页事件为 `@pagination:size-change` / `@pagination:current-change`；插槽名=列 prop 且需 `useSlot: true`
- `useTable` 返回值语义：`replaceSearchParams` 只换参不请求（需再 `fetchData()`）；`resetSearchParams` 自带请求；5 种刷新 refreshCreate/Update/Remove/Data/Soft
- 删除目录注意：沙箱 rm 会走回收站且可能失败，临时目录用 PowerShell `Remove-Item -Recurse -Force` 清理

- 前端：Vue3+Vite（端口配置 `.env` 的 `VITE_PORT=3006`），实际 dev 常落在 **3007**（3006 被占时 Vite 自动+1）；dev 模式 `/api` 代理到 apifoxmock（`.env.development` 的 `VITE_API_PROXY_URL`），**不依赖后端即可看界面**
